# ADR 0003：库存与融卡共享一个事务模块

日期：2026-10-26。状态：开发分支实施，未部署。

## 问题

主入口原来同时包含库存回放、每日额度、材料与等级校验、幂等请求、随机结果、融卡写入和账户输出。抽取其中任何一个小函数，仍会让调用方了解整套规则与事务顺序。

## 决定

新增 `server/card-collection.mjs`，对外只提供 `read(userId)` 与 `fuse(userId,payload)`。

`read`集中返回原有inventory、fusionDaily和fusions字段。库存仍由原始draws及card_fusions回放得出；不重写抽卡历史，不创建第二份余额或库存表。

`fuse`内部保留完整流程：身份验证、请求格式、BEGIN IMMEDIATE事务、同一岛民的请求幂等、每日3次、材料与库存验证、按当前公开卡池选择结果、持久化记录及读取新账户状态。复用现有事务、认证、目录、随机和时钟依赖，不复制另一套事务实现。

主入口只组合账户状态和转发路由。状态回调仍在事务内读取，失败会让整次融卡回滚；重复请求仍在配额检查之前返回原结果。

## 不变项与验证

- N/R/SR产出规则、公开卡池过滤、北京时间00:00重置及每日3次不改变。
- 同卡材料仍要求至少2张；请求编号只在同一岛民范围内去重。
- 权限与错误检查顺序、返回字段、历史顺序及最近50条限制不改变。
- 不新增数据库结构，不写金币流水，不增加活动期门禁；原有活动期外融卡能力保留。
- 模块测试使用真实临时SQLite，覆盖持久化、用户隔离、配额、北京跨日、重复请求、数据库写入失败及profile读取失败回滚。
- 既有融卡及临时委托HTTP集成测试继续检查实际接入。

本批基于当前已上线后台分组版本0135dc2，保留现有后台及兑换码功能，不包含另外两批尚未部署的前端架构改动。
