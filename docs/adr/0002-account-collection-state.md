# ADR 0002：集中账户与目录状态投影

日期：2026-10-26。状态：已在开发分支实施，未部署。

## 问题

app.js同时负责请求、DOM、账户与目录的先后顺序、真实卡片ID到展示ID的映射、抽卡历史、融卡库存覆盖及手机快照。新增一个收藏展示方式需要再次理解这些约束；旧测试还需要构造多个内部变量。

## 决定

新增无DOM依赖的 `account-collection-state.js`。模块持有目录状态、账户响应关联、版本失效标记及两种卡片编号索引，负责现有profile到页面状态的投影，以及安全的卡册快照。

浏览器适配器提供现有request和令牌读取函数；模块不使用fetch、sessionStorage或数据库。`load`协调目录与账户独立请求并通知适配器；`acceptProfile`投影原账户；`snapshot`输出展示数据；`invalidateProfile`保留现有默契小测对旧请求的失效机制。只读元数据供现有抽卡及融卡界面读取。

app.js保留页面重绘条件、错误提示、令牌持久化和退出处理，不把奖励行为放入状态模块。目录到达后触发profile重投影的页面决策仍留在适配器，避免本轮改变页面重绘时机。所有引用app.js的页面在其之前加载模块，并同步更新缓存版本。

## 保持的行为

- 目录、账户、素材及OC加载互不阻塞登录。
- 请求开始时的令牌与版本用于同时检查成功、401和临时错误响应。
- 非401错误保留会话；401仅清除仍属于当前账户的会话。
- 真正库存覆盖原始抽卡数量，保留现有抽卡和融卡历史插入顺序。
- 首抽判断、金币、奖励、配额、后端规则、主页视觉不改变。
- 静态演示模式使用原有演示状态；真实快照不包含令牌或原始账户对象。

## 验证与代价

模块接口测试覆盖两种完成顺序、映射、库存覆盖、多条历史顺序、过期成功及失败响应、401、503和匿名状态。真实API浏览器检查覆盖10个正式共用入口与1个静态预览入口。原有加载、登录、委托与手机体验测试继续验证接入。

测试适配：loading-flow原有源码抽取harness改为注入真实模块；mobile-experience手机筛选断言使用此前已上线的卡册弹窗，桌面仍检查原标签。两项均未改变运行行为。

代价：浏览器需按序加载一个额外静态脚本；发布打包已自动覆盖整个ui-preview目录。后端库存及融卡事务模块仍未改动。
