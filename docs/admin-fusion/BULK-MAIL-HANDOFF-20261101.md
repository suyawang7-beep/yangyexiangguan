# 全岛信箱寄送｜开发交接

## 状态和边界

已实现真实API与新旧后台共用寄送表单，未部署本轮功能、未连接或修改生产、未向真实岛民寄送。正式环境仍为信箱领取版51b3774。Work视觉文件未改动。

## 操作与范围

在 /admin/v2/ → 活动与内容 → 信箱及物品寄送，选择“全部已注册岛民（含未认证）”。填写原礼品、标题、留言和原因后先预览：固定当时users表账号快照，显示认证/未认证人数、每人礼品、精确总量和时间。未注册浏览会话不包含；不是按已认证筛选，未认证注册账号也收到信件，但仍沿用认证后才可读取及领取的权限规则。快照后新注册账号不自动加入。

二次确认后逐批创建邮件，每次HTTP最多50人。金币及次数均不即时入账。融卡次数仍在领取当日生效、北京时间次日00:00失效。页面展示已寄、待寄及失败；失败不会阻止其他收件人，补寄仅重新处理失败者。离开页面、重启或断网后从最近20个批次查看/恢复，不会后台定时自动发送。批次已创建与奖励已领取明确区分。

响应丢失时锁定原内容，并显示“重试上一未确认操作”；即使刷新进度后确认按钮被隐藏，也可以重放原请求，不能更换礼品/收件范围重建不明批次。各入口阻止覆盖单封或群发未确认请求。

## 数据契约

全部接口沿用现有 /api/admin 管理员服务端鉴权（一次登录）。没有第二套账号或资产通道。共享管理员凭据系统只能记录actor=admin，不虚构具体人员身份，也不记录凭据。

- POST /api/admin/island-mail/batches/preview：原礼品字段+UUID requestId；持久化草稿及收件人快照，不创建邮件。相同编号同内容幂等，改内容409。
- POST .../confirm：id、expectedRevision、confirmed=true，锁定预览版本；仅设置已确认，不声称已发送。
- POST .../process：id，仅处理待寄收件人，返回当前统计；未确认409。
- POST .../retry：id、UUID requestId、confirmed=true；原子将失败者置回待寄。同一次重试不能重置后来发生的失败。已成功者永不重寄。
- GET .../batches?id=UUID：批次、礼品、范围、统计及最多前50条失败摘要（固定错误码，不暴露内部异常）。无id返回最近20批。

新增3表：island_mail_batches（礼品/版本/操作者/时间）、island_mail_batch_recipients（快照/逐人状态/邮件关联）、island_mail_batch_retries（重试请求幂等）。新增待寄索引；不修改旧数据和金额。完整SQLite备份自动包含新增表；运营JSON导出也明确包含三表。

每位收件人的邮件创建、融合奖励映射、原因、mail.send审计、批次进度和delivery审计共用BEGIN IMMEDIATE事务。邮件request_id由批次ID+账号确定，跨进程与重试稳定。任何一步失败全部回滚，再单独标记失败；不会出现邮件已提交但进度仍待寄。

用户ID快照保留为运营历史而不强制外键，允许原有管理员游客删除；mail_id外键ON DELETE SET NULL，删除账号关联邮件后批次仍记为历史成功，不会重新发送。未发送前账号被明确删除则正常记录寄送失败，不自动重建账号。
