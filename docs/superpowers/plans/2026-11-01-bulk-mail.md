# 全岛信箱寄送 Implementation Plan

Goal: 在同一信箱表单加入全体已注册账号收件范围，以邮件形式发放维护补偿；仅本地合成数据验证，不发布或真实群发。

Architecture: SQLite持久化不可变的礼品及收件人快照，管理员预览后明确确认；每次请求最多处理50封，逐人事务复用原邮件写入及原领取事务。批次及逐人幂等，失败独立保留并仅重试失败者，支持刷新/重启续发。

Scope: users表全部已注册账户（含未认证；游客浏览会话不在users表）。未认证注册账号会收到邮件，认证前仍按现有规则不可领取。确认页显示认证/未认证数量、每人及总量，快照后新增账号不纳入。管理员仅共享身份admin，不虚构独立操作者。

Files: server/mail-batches.mjs负责批次；server/index.mjs复用邮件校验及事务内部写入并接路由；admin/index.html保留表单并接群发面板；admin/mail-batches.js负责批次交互，生成器编译进v2；tests/mail-batches.mjs使用独立HTTP/SQLite验证。Work视觉文件不改。

- [x] 1. 编写并观察合成HTTP测试失败：快照、确认、重复创建、无即时奖励、权限、部分失败、补失败及领取。
- [x] 2. 实现批次表、分批事务、稳定邮件编号、进度/审计及服务端校验，运行测试。
- [x] 3. 接入同一旧/新后台表单、双确认、锁定未知请求、可恢复批次记录，做浏览器交互验证。
- [x] 4. 运行信箱及生成器相关定向回归，记录结果与未上线状态，提交独立成果。

Risks: 不允许发送成功后因进度更新失败造成未关联邮件，必须同事务。审计故障时对应邮件回滚；故障记录用固定错误码，不输出堆栈/凭据。处理中断后已成功者不可重寄。预览草稿不自动发送；无人在线时须明确点击继续发送。
