# 后端收藏与融卡模块 Implementation Plan

> 使用 executing-plans 逐步实施第三批架构整理，基于已上线的0135dc2，不混入尚未部署的前端重构。

目标：把库存回放、北京时间每日额度、幂等、材料验证、结果选择及事务写入保留在一个深模块。公开read与fuse两项行为，主入口只保留路由和账户总状态组合。

约束：不改变概率、稀有度规则、每日3次、权限、重试顺序、事务边界或历史；不迁移数据库，不修改生产环境。既有融卡在活动期外可用的行为保持。

步骤：
- [x] 新接口缺失时测试先失败，之后使用真实临时SQLite验证。
- [x] 原样迁移库存与融卡逻辑，复用既有BEGIN IMMEDIATE事务函数和实际账户状态回调。
- [x] 库存归属、等级、配额、北京跨日、用户内幂等、不同同等级材料、插入及profile失败回滚、重连持久化、全历史回放与最近50条展示通过。
- [x] 既有card-fusion及commission-coin-code HTTP集成通过。受限网络无法连接本机服务时，使用获准的本机网络权限运行隔离测试，不连接生产。
- [x] 独立审查确认原逻辑在依赖名替换后保持一致，初始化、事务与返回数据无回归。独立提交与PR交付，不部署。
