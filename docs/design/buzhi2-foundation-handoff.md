# 不吱岛 2.0：多页面工程与视觉交接说明

## 责任分工
- 工程侧：页面与导航架构、交互状态、表单处理、安全校验、测试与业务接线。
- 视觉侧（隔壁）：各页面的独立空间构图、角色立绘/背景板/卡面商品图、组件视觉系统、动效细节与响应式视觉调整。

## 开发与部署边界
- 本分支来源：preview/buzhi-2-zhizhi-20261027（不是 main）。
- 本分支包含原测试预览 Dockerfile：nginx 静态展示；**严禁直接合并到 main 或覆盖生产 Dockerfile**。
- 本分支仅包含 UI 演示，不连接任何生产 API、账户、SQLite、金币、卡牌扣除或兑换记录。
- 静态业务模拟不得生成伪造交易成功提示。
- 不调整原有卡牌经济与奖励规则；合成配方、库存、兑换条件待岛主正式确认。

## 视觉侧可以修改
- `ui-preview/buzhi2/foundation.css`：颜色、排版、布局、响应式与组件视觉。
- `ui-preview/buzhi2/foundation.js`：各页面模板中的 DOM 结构，但保留 data-page 路由、页面链接、ARIA 状态、禁用交易按钮以及安全提示。
- 新增独立资源目录 `ui-preview/buzhi2/assets-v2/` 存放图片，不要复制旧岛民真实数据。
- 每个 HTML 文件保留 data-page 与 foundation.js 引用。
- 可完全推翻当前「左右结构」和卡片外观；这是可替换的语义骨架，不是被批准的设计稿。

## 建议视觉方向（非强制）
- 首页：沉浸式舞台/全景岛屿；**不要传统左标题右人物＋下排卡片**。
- 融卡：卡牌操作台布局，配方区与核对结果分离。
- 商店：陈列室布局，筛选、详情与库存状态清楚。
- 收藏：陈列画廊，重视卡面观赏。
- 信箱：信纸与投递流程。
- 个人中心：岛民档案界面。
- 导览：可视化路线。
- 所有页面需独立设计桌面与手机信息结构，保证键盘可达与减少动效。

## 与现有正式站衔接注意事项
正式站的 ui-preview/app.js 使用原有服务端逻辑；目前这套新骨架**没有整合**该逻辑。工程合并前必须逐项比对接口和现有测试，不能用静态骨架覆盖真实页面。
