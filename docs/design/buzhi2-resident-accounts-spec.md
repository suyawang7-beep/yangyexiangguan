# 不吱岛 2.0 · 长期岛民账号升级契约

状态：需求及工程契约草案，不是已经上线或完成的认证后端。基于 2026-10-27 `main:ui-preview/app.js` 账户流程核对。

## 已存在，禁止重复造轮子
- 正式版新岛民：昵称 1–20 字、密码 10–128 字注册；后端 `register` 返回 token、profile 和恢复密钥。
- 老岛民：`login` 使用岛民编号+密码或原恢复密钥。
- `recovery/request` 通过岛民编号、已认证抖音号发起人工审核找回，`recovery/reset` 用一次性凭证设置新密码。
- `me` 返回账户、金币、流水、卡片等资料；登录态是现有真正的业务身份。不得用新本地账户替代。

## 2.0 待新增或待后端确认

1. **稳定账号名（username）**：与公开昵称（nickname）分离；账号名唯一、可登录。保留原 BZI 编号和老密码/密钥登录，老账户不强制抢注用户名。
2. **昵称编辑**：用户自主更换公开昵称；长度、过滤规则由业务侧确认；服务器写审计记录；不要拿昵称作为主键。
3. **修改密码**：登录后输入旧密码再设置新密码（10–128 字），校验当前会话、限流、原密钥迁移兼容。
4. **退出登录**：仅清除当前会话令牌，清理当前页的私密显示、取消进行中的账户请求；不得删除账户、金币、OC、收藏和历史。若后端支持失效令牌，则请求服务端撤销；明确与「退出所有设备」区分。
5. **登录异常提示**：离线/401/403/429/超时分开。401 清除无效会话；网络错误保留可恢复登录态，不将余额视为 0。
6. **账号安全**：密码服务端带随机盐的慢哈希，禁止明文保存、记录或放在 URL；登录/找回限流；重置凭证一次性、过期、最小权限；避免公开抖音号与个人密钥。
7. **账户设置**：昵称、头像、账号名（不可与编号混淆）、密码修改、认证状态、登岛历史、退出登录；支持个人中心清晰进入。
8. **资料与资产一致**：沿用原用户 ID 关联金币、卡牌、任务、签到、兑换和 OC；任何 UI 改版不得重建用户或导入演示数据覆盖。
9. **冲突与迁移**：旧岛民没有 username 时仍可使用编号登录；账号名重复返回具体冲突错误；数据迁移需备份、幂等检查、回滚方案。
10. **验收**：新注册、已有账号登录、旧密钥迁移、同名昵称、重复账号名、密码变更、退出后后退访问、跨设备登录、账户找回、弱网/失效会话、资产不变。

## 视觉与工程约定

登录入口位于全站顶部导览；游客只显示登录，登录后显示账户入口与退出登录。
手机端放到导航抽屉/账户菜单，但不可隐藏基本登录入口。
`ui-preview/buzhi2` 当前仍是静态预览，不接真实账号 API；不要要求用户输入真实密码。
下一步必须先定位正式后端对应路由/数据模型，再建立迁移与接口测试，不能从前端请求推断所有服务端能力。
