# 不吱岛 2.0 · 非方正布局与交互约束

> 2026-10-27 用户确认：现有工程预览「太方正了」。此文是供视觉侧与工程侧共同使用的实现要求；不是已经完成的视觉验收，也不授权生产部署。

## 总原则

- **不要**沿用「标题左 / 人物右 / 下方一排等宽卡片」的首页骨架。多页面架构应保留，但每个页面可有不同的空间语言。
- **不要**把所有页面包在相同圆角玻璃大矩形中；也不要用单纯增大圆角冒充改版。
- 视觉形态从岛屿、潮汐、信纸、卡牌、陈列、手账与人物关系自然生长：不对称、错层、前后景、少量悬浮与局部重叠；装饰需服务叙事或操作。
- 避免只追求“流动”：核心任务文字与表单应保持稳定阅读网格，用户无需寻找按钮。
- 首页承担世界观与导航，功能在独立页面完成；**不得重新做成长单页**。

## 设计可变区 / 工程不可破坏区

**视觉侧可改**：DOM 容器结构、CSS Grid/Flex 结构、插画/材质、SVG 装饰、局部 overlap、动画和前景层、桌面与手机断点、导航外观。

**必须保留**：
1. 真实导航与目的地：`index.html`、`birthday.html`、`workshop.html`、`shop.html`、`collection.html`、`mailbox.html`、`office.html`、`resident.html`、`guide.html`；链接不可是假按钮或跳错旧版。
2. 页面键盘焦点、Tab 顺序、语义按钮与标签；活动抽屉/对话框支持关闭、返回和失焦管理。
3. 手机至少 320px 起可用，控件触控目标建议≥44×44 CSS px；正文与状态清晰，不允许主体水平溢出。
4. 对动画敏感者：尊重 `prefers-reduced-motion`，不强制开场、不劫持滚动、不用无限持续光效遮文字。
5. 未接通真实业务前，禁止模拟真实领金币、融卡、兑换、登录成功；所有金额、材料、库存、日期及开放状态以服务端或岛主确认规则为准。
6. 禁止随意更改卡池、抽取历史、领取记录、数据库、账号/认证；部署与迁移单独授权。

## 实现策略
- **形状**：可用 CSS `clip-path`、mask、SVG 边框和少量绝对定位做有机边缘，但文本和交互热区维持稳定布局。
- **分层**：背景装饰 `pointer-events:none`，不阻挡输入；角色立绘须能在手机端安全裁切。
- **移动端**：不是把桌面错层缩小；改为纵向场景、可滑动的独立选择区、抽屉式详情，默认展示最重要入口。
- **动效**：优先纯 CSS transform/opacity，仅长序列动画再考虑 GSAP；不可用动效做关键内容的唯一传递方式。
- **资源**：隔壁提供可替换角色立绘、建筑场景、卡面等独立资源，页面文字和按钮不烘焙进背景图。

## 视觉完成后工程验收

- 同一页面在 320、375、390、768、1440px 视口下截图审查：无裁字、遮挡、横向溢出；移动端 CTA 可见可按。
- 键盘从导航到主要操作能完整行走，面板切换、关闭、返回可操作。
- 逐页核对链接和用户状态：未登录、待认证、规则未确认、关闭活动、空收藏、加载失败。
- 对比“改版前/后”桌面与手机截图，**审查页面空间骨架是否真实改变**，不是仅改背景、颜色或圆角。
- 测试环境先走全部关键路径；未通过或未确认的功能保持禁用。正式部署按备份/回滚流程另行授权。
