来源：[alchaincyf/huashu-design](https://github.com/alchaincyf/huashu-design)。已保存核心说明、MIT 许可和选取的网页/评审参考，版本与逐文件哈希见 [SOURCE.json](vendor/huashu-design/SOURCE.json)。没有全局安装，也未运行脚本、钩子、偏好采集或更新命令。完整仓库的脚本、媒体与其他模块没有导入，原文中指向这些文件的链接可能不可用。

## 对不吱岛最有价值的部分

- 新方向在结构、主角比例和交互上形成真实差异，避免只换色、换圆角。
- 从已有角色立绘、卡面、品牌和业务出发，再决定构图；占位图不冒充正式角色素材。
- 以中文排印、阅读顺序、信息密度和主次判断布局；不以装饰数量判断精致程度。
- 候选先形成可见初稿再选择，不只列风格名；已选定方向的迭代不反复开启全套选型。
- 评审区分内容、构图、交互和工程问题；实际截图、状态和操作证据优先，不把静态检查通过当成视觉验收。
- 模拟艺术总监、视觉、文案、动效和工程视角进行复核，不意味着必须额外启动多个代理。

## 使用边界

该 Skill 明确面向 HTML 视觉原型、设计探索等产出，生产级 Web App 和后端系统不在适用范围。可以用来探索生日首页预设，再按本项目的测试、权限、数据和部署要求实现。不能据此重写金币、抽卡或认证逻辑。

与 StyleKit 的分工：Huashu 负责方向差异、内容构图和评审，StyleKit 负责具体风格规格及一致性；GSAP 负责选定交互的时间轴与清理。简单交互仍可用 CSS。

第三方提出的自动记录用户偏好、截图工具安装、脚本执行和文件上传均不自动启用。已有用户决定和项目约束优先；本次只是学习资料与保存参考，不启动新一轮三方向设计或改动页面。
