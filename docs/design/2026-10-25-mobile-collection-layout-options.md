# 手机版收藏室 · GitHub排版参考

2026-10-25。用户反馈当前收藏室手机页面太长，本轮只研究与比较，没有修改运行页面或部署。

## 需要改变的结构

当前封面统计、筛选、展示方式、扇形展台、完整网格、装饰及开信历史纵向串联，导致重复展示同一批卡。手机应改为“卡册 / 欣赏 / 记录”三个互斥内容标签；完整网格仍可访问，但不再与大展台同时纵向铺开。桌面可保留并列功能及完整网格。

共用：紧凑标题与收藏进度、独立筛选抽屉、当前筛选数、明确清空/应用、原有网站底部导航；普通手机常态目标约一屏，短屏/大字体允许自然滚动，不强制裁切。所有持有数量、60卡定义、历史及后端接口不变。

## A：海岛口袋卡册（推荐）

- 默认纸质卡册，一页4张（2×2）；较大屏可评估6张。左右横滑翻页，显示页码和前后按钮。
- 卡片像装在透明卡袋里，保留海盐蓝、奶油白、少量贴纸；点击放大，故事按需打开。
- 欣赏标签切换到现有大卡展台，记录标签显示历史；默认不叠加长列表。
- 初版采用轻分页；拟真纸张翻页为可选装饰，需验证触摸滚动、减少动态及性能。
- 参考 [StPageFlip](https://github.com/Nodlik/StPageFlip)，[官方示例](https://nodlik.github.io/StPageFlip/demo.html)。已阅读README并在浏览器实际翻页。其支持HTML内容、移动端和竖屏；4/6卡片布局是本项目拟议设计，并非源项目现成功能。

## B：单卡沉浸展台

- 默认一张完整大卡，两侧露出下一张边缘，左右滑动切换。
- 名字、稀有度、数量在卡片附近，故事详情弹出；卡册与记录放到其他标签。
- 更适合欣赏人物与卡面；寻找指定卡片时借助筛选或卡册标签。
- 参考 [Swiper](https://github.com/nolimits4web/swiper)，[Cards官方示例](https://swiperjs.com/demos#effect-cards)。已查看官方叠放示例，README确认触屏、分页、模块化和原生JS接入。延续现有扇形也可，不必为布局强制更换组件。

## 辅助参考

- [Pokédex Card Tracker](https://github.com/mnelson0118/pokemon-card-tracker)：README明确提供手机紧凑标题、折叠筛选、状态筛选及点击看大图；只借用信息结构，不采用其Firebase或手动标记收藏逻辑。
- [PhotoSwipe](https://github.com/dimsemenov/PhotoSwipe)，[官方演示](https://photoswipe.com/)：参考图片放大与独立查看层。不是完整收藏排版或账户系统，本轮仅阅读README，未完成手机真机体验。

## 核实范围

已核对上述GitHub说明，并打开Swiper与StPageFlip官方示例，实际操作了翻页。没有声称它们已经在不吱岛运行，也未安装依赖或完成手机真机性能验收。视觉风格沿用本项目，不复制示例的配色和内容。

建议先选择A或B做390px的可点击本地预设，验收默认高度、翻页、筛选和详情后再改正式组件。
