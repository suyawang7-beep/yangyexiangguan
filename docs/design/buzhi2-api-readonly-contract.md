# 不吱岛 2.0 · 业务接线清单（只读基线）

日期：2026-10-27；读取自 main 的 `ui-preview/app.js` 源码。**只审查了现有前端调用，不代表已核对服务器所有路由、权限或返回格式**。

## 当前已由源码证实的客户端读取路径

| 旧站调用 | 原前端可见行为 | 2.0 目标页面 | 注意 |
| --- | --- | --- | --- |
| GET `/api/catalog` | 接受 `{cards,totalSlots}`，同步卡片目录 | 收藏、融卡卡牌选择 | 空目录与加载失败分开；只读 |
| GET `/api/me` | 会话校验、余额、任务、抽卡、流水等 | 个人中心、收藏、事务所 | 401清空无效会话；网络异常不能显示零金币 |
| GET `/api/oc` | 读取人物资料 | OC画廊、个人中心 | 公共人物不能冒充个人绑定OC |
| GET `/api/assets-manifest` | assets、versions、layouts | 所有含图库页面 | 有原图布局元数据，不覆盖后台素材 |
| GET `/api/announcements` | 岛主公告 | 首页、信箱 | 不把设计稿示例当作真实公告 |

旧站前端 `liveApi` 用 `Authorization: Bearer` 传会话、15秒部分请求超时及服务器错误处理。这些行为需要与真实后端权限一致后再迁移；不要把 sessionStorage 中的令牌写进 URL、日志或静态构建产物。

## 本次新代码

- `ui-preview/buzhi2/state-model.js`：纯函数状态模型，支持 `idle/loading/ready/empty/error/unavailable`，访客/已登录等会话区分、开放状态守卫与只读白名单。
- `tests/buzhi2-state.test.cjs`：Node 内置测试（`node --test tests/buzhi2-state.test.cjs`），检查预览无网络请求、关停或规则未知时操作禁用、缺失账户不会误判0金币、白名单拒绝交易 URL。
- **重要：尚未将只读模型接入页面展示**。当前预览仍显示明确的静态占位；必须检查正式 API 返回格式并复核鉴权后才可以启用非预览读取。

## 后续工程阶段

1. 逐个读取真实后端文件，核对响应结构、分页、隐私与权限：仅基于前端的猜测不能直接接线。
2. 在隔离测试环境写 `transport`，明确区分只读获取与交易命令。只读阶段优先公开公告/目录，不以公开网页读取登录态。
3. 建立共享页面状态与角色权限契约（loading/empty/error/offline/forbidden/auth-expired/scheduled/open/closed）。
4. 交易命令融卡、兑换必须由服务端校验材料、资格、库存与幂等键；后台规则未确认，不实现提交。
5. 视觉侧用状态模型驱动组件，但不可写死“已开放”、余额、库存、生日日期。
6. 单元、浏览器和实际服务端集成测试通过后，才讨论灰度上线与回滚。
