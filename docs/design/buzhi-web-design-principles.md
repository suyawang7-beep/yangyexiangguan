# 不吱岛网页设计与审查准则

来源：用户于2026-10-27明确要求，后续网页相关工作持续参考本次8个仓库与此前已使用的设计技能。按任务选择适用原则，不将全部技能原文机械叠加，也不把教程、视频工具当作网站运行依赖。

## 产品与品牌

不吱岛面向岛民，是能留下故事、信件、卡片与角色回忆的小世界。保留已确认的海蓝色、奶油白、海岛、灯塔、海鸥、角色插画与手绘日记语言。玻璃质感有品牌依据；根据阅读和层级控制用量。通用“反模板”规则不能覆盖用户确定的品牌方向。

生日首页以当期主角和祝福为中心；日期、角色资料和素材未核实前，不虚构。金币及抽卡是参与路径，首页不做奖励数字驱动的营销页面。

## 按页面目的选择表达

- 生日首页：一处最鲜明的主视觉、明确主角、真实日期、一个主行动。
- 收藏与OC画廊：作品和人物先于操作面板，保留高效查找与故事阅读。
- 个人中心、事务所、信箱、认证：优先完成任务，界面简洁但保留小岛温度。
- 导览和帮助：地图与信息对应清楚，支持触屏、键盘与返回总览。
- 后台：状态、权限、生效时间和保存反馈清楚，装饰服从操作效率。

## 页面与移动端

使用统一颜色、字阶、间距、圆角、阴影和层级；首页、内容页、后台各有适当密度。先确定视觉主次，再加装饰，避免所有模块都套相同大圆角玻璃卡。

手机首屏保留主角/个人形象、核心状态和核心操作；次要操作使用标签、折叠栏或底部面板。不要为了塞进一屏缩小文字、裁掉内容或关闭缩放。手绘字体用于短标题，正文和表单保持清晰。

交互覆盖默认、悬停、焦点、按下、禁用、加载、错误和成功。支持键盘、触屏和减少动态效果；触控目标以44px为设计基线。对比度、短屏、放大和长文案需要实测，不能凭截图或规则宣称完全合规。

## 动效与性能

每个动画都应解释状态变化、反馈或连续性；生日首页可以有一次短叙事，任务操作保持快速。优先transform/opacity，可打断、可关闭，并尊重prefers-reduced-motion。手机不依赖hover，不使用滚动劫持或覆盖文字的持续特效。

先用现有HTML/CSS/JavaScript和素材，不因视觉改动重构整站。图片按尺寸处理、预留布局空间、按需加载；视频与大型动画工具需有实际用途，默认不引入。

## 真实状态与安全

首页、抽卡和事务所入口应与后端实际开放状态一致。加载未知不显示虚假零值；领取成功、金币到账及任务完成以服务器响应为准。只在账户真正绑定时展示“我的OC”。已有账号、金币、卡片、历史、素材和权限隔离必须保留。

设计先区分已观察事实、代码风险和建议。没有当前截图时只能做代码/结构评估，不能伪称完成实时视觉验收或给出测量分数。先做一版，再审查、调整与验收；发布遵循用户确认、备份和回滚要求。

## 资料角色

- [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)：设计系统、响应式、可用性和无障碍检查。
- [中文教程](https://github.com/bbylw/ui-ux-pro-max-skill-cn)：理解与使用辅助，不重复当作另一套规则。
- [Impeccable](https://github.com/pbakaus/impeccable)：区分审查、简化、精修与重设计，按页面目的控制表达。
- [Design Taste](https://github.com/h3nryprod01/design-taste)：排版、层次、交互状态与二次自检，结合品牌取舍。
- [Frontend System Design](https://github.com/devkodeio/frontend-system-design)：状态、性能、边界场景与工程交付检查。
- [Namaste Frontend System Design](https://github.com/namastedev/namaste-frontend-system-design)：安全、测试、性能与可访问性专题。
- [HyperFrames](https://github.com/heygen-com/hyperframes)：可选的生日短片制作，不是默认整站动效框架。
- [Grill Me](https://github.com/RobMitt/grill-me-skill)：只对关键未决问题做需求澄清；代码可回答的问题先自行检查，避免重复追问。

继续结合本地frontend-design、animate、mobile-native和review-animations。新增技能的阅读、安装和实际工具运行必须分别如实记录。
