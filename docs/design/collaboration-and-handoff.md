# 不吱岛：工程、视觉分工与额度交接规则

更新：2026-10-27。用户明确要求：GPT负责搭建布局与多页面骨架，Codex负责页面美观；每轮接近额度上限前，提前留下隔壁可以接手的文件或仓库说明。

## 分工

- GPT工程侧：页面与导航架构、交互状态、表单处理、安全校验、测试和业务接线。
- Codex视觉侧：在确认的工程骨架上处理各页空间构图、素材、字体、层级、组件样式、动效与手机响应式；不另起不相干的网站，不无故重建业务骨架。
- 如果美化需要改变DOM，保留data-page、跨页链接、ARIA状态、禁用交易按钮和安全提示；需要新增业务或改变规则时，作为工程待办明确交接。
- 工程交接建议的视觉结构不是已验收设计。用户对布局的更新选择优先，不把旧预设当成最终标准。

## 每轮收尾与额度检查点

不要等到额度耗尽才整理。每完成一个可以独立验收的小阶段，就保存一次简短检查点；用户提示额度不足时优先保全成果，暂停扩展范围。

交接文件至少包含：

1. 当前分支、基线提交、最新提交及远端链接；是否已推送，未提交文件有哪些。
2. 已完成页面与具体修改文件；区分真实功能、静态预设、待接线按钮及占位素材。
3. 验证命令、运行时间、结果和截图路径；未运行或受阻的检查明确写出。
4. 剩余任务按顺序列出，给出下一个最小可执行动作及相关文件。
5. 已知问题、用户已确认的决定，以及仍需确认的设计或业务事项。
6. 生产状态、是否部署、备份与回滚资料位置；没有操作就明确写未操作。
7. 不保存密钥、令牌、私钥口令、真实用户数据或含凭据配置。

建议命名：`docs/design/handoffs/YYYY-MM-DD-主题-handoff.md`。当轮最终答复提供文件/仓库链接；有推送授权时及时推到开发分支，未推送时明确说明。推送不等于合并或部署授权。

不能保证提前获知精确的额度耗尽时刻；以用户提示及可用状态为依据，采用分阶段检查点降低突然中断造成的损失。不得声称存在没有设置的自动提醒或自动交接。
