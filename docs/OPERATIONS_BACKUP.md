# 运营备份与数据导出

后台 `/admin` 提供“运营备份与导出”。所有接口均要求现有管理员 Bearer 密钥；密钥不放入下载链接或浏览器长期存储。普通参与者令牌不具备导出权限。

## 数据库快照

点击“创建数据库备份”后，使用 SQLite `VACUUM INTO` 生成一致性快照，并以独立只读连接执行 `quick_check`。验证通过才进入可下载列表。快照位于数据库同级 `backups/`，Railway 上通常为 `/data/backups/`。

完整快照包含数据库全部表，包括账户凭证摘要、会话摘要及任务兑换码摘要；只供岛主保密保管。它包含金币、任务、签到、卡片及活动配置，**不包含上传的图片文件**。图片目录通常为 `/data/assets/`，需另外备份。

这不是定时或站外备份。仅在原 Volume 内保留快照不能防范整个 Volume 丢失，管理员应主动下载到自己的安全位置。界面不提供覆盖生产库的恢复或删除按钮；不能将下载的快照直接上传覆盖正在运行的数据库。

系统不会自动删除旧备份。同目录 `.sqlite` 达到 50 份，或这些文件总量加预计新快照超过 200 MiB 时，拒绝新建并提示运维离线转存处理。已有测试清理备份计入容量，但手动列表仅展示本功能创建的快照。快照创建需要短暂数据库工作时间，宜避开参与高峰。

## 运营 JSON

点击“下载运营 JSON”导出同一读事务中的完整运营记录，不沿用后台概览的 100 条显示限制。

- 包含参与者编号、昵称、注册时间和计算余额；金币流水、任务、阶段奖励、签到、抽卡、公告、活动时间、视效设置与素材布局。
- 排除恢复密钥摘要、会话表、兑换码表以及管理员审计原文。管理员密钥、登录令牌、恢复密钥及兑换码明文不会进入导出。
- `format` 为 `buzhi-operations`，`version` 为 `1`；`exportedAt` 使用 UTC ISO 时间，`timezone` 指明北京时间。
- JSON 用于运营查阅与统计，不能替代可完整恢复数据库的 SQLite 快照。昵称等仍是参与者资料，请按运营需要保管。

## 接口

| 方法与路径 | 功能 |
| --- | --- |
| GET /api/admin/backups | 手动快照名称、大小、创建时间，无服务器绝对路径 |
| POST /api/admin/backups | 创建并校验快照，JSON 请求体可为 `{}` |
| GET /api/admin/backups/download?name=… | 下载严格文件名校验后的手动快照 |
| GET /api/admin/export | 下载运营 JSON |

下载响应使用 `attachment`、`private, no-store` 与 `nosniff`。不存在公开 `/backups/` 路由。创建、下载和导出写入管理审计，不更新或删除参与者及奖励记录。

## 验证

`tests/operations-flow.mjs` 使用临时数据库验证权限、WAL 最新数据、下载快照独立完整性、106 个参与者无截断导出、凭证排除、业务数据不变性、路径校验、无公开下载及恢复入口、审计、保留上限。

`tests/operations-admin.cjs` 在桌面和手机宽度实际创建备份、下载并打开 SQLite、下载 JSON，验证退出后面板隐藏。测试不会连接生产数据库，也不会自动创建或下载生产快照。
