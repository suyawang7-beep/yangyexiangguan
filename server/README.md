# 不吱岛 · 正式数据服务（第一阶段）

独立于静态首页的 Node.js 24+ / SQLite 服务。无 npm 依赖。

## 启动
1. 在服务端设置环境变量 `ADMIN_TOKEN`（至少 32 字符），并选择有持久化磁盘的 `DB_PATH`。
2. 在 `server/` 下执行 `npm start`（或 `node index.mjs`）。
3. HTTP 监听 `PORT`，默认为 4178；生产环境必须置于 HTTPS 反向代理后，且只允许可信来源。
4. 默认仅绑定 127.0.0.1；要经由反代运行时，请设置 `HOST`。

> 注意：这不是云端部署，也没有主动为你创建数据库实例。必须在持久化服务器部署以后，跨设备数据才能生效。前端当前继续运行本地演示逻辑。

## 接口协议
- `POST /api/register`：`{nickname}`；返回岛民 `id` 与只展示一次的 `recoveryKey`。昵称可重复。初次报到计入一个不同任务。
- `POST /api/login`：`{id,recoveryKey}`；返回 12 小时会话 token。请勿将恢复密钥放在 URL 中。
- `GET /api/me`：请求头 `Authorization: Bearer <token>`；读取金币余额、任务、签到、卡片。
- `POST /api/redeem`：`{taskId,code}`，岛民令牌；一个完成代码只能使用一次，且与指定任务绑定。
- `POST /api/checkin`：当日签到仅一次，使用服务器 UTC 日期（正式上线前可按活动时区调整）。
- `POST /api/draw`：单抽扣 50 金币；首抽保底 SR/SSR；后续 16 张等概率。
- `POST /api/admin/codes`：`{taskId,count}`；请求头 `Authorization: Bearer <ADMIN_TOKEN>`；返回一次性代码明文，管理员应安全分发。
- `GET /api/admin/overview`：管理员令牌；返回参与人数、任务兑换数、抽卡数。

所有金币变化均写入 `ledger`，任务领取、金币扣费、抽卡入库使用同一数据库事务，避免重复请求造成重复结算。没有管理员网页面板；本阶段实现最小管理 API。

## 安全边界与上线检查
- 恢复密钥、任务码及会话令牌仅保存服务端 SHA-256 摘要；恢复密钥须由岛民妥善保管，丢失无法自助跨设备登录。
- 管理令牌必须是服务端环境变量；请使用 HTTPS、访问限流、持久备份和安全审计；需要完整生产安全审核。
- 管理接口应进一步加 IP 允许列表、操作日志；当前未实现账号找回及管理员角色分级。
- 仍需完成**前端在线登录 UI 与 API 联动**；这份服务代码不会自动替代页面的 localStorage 演示账户。
- 项目不收集真实姓名等必要性不高的资料。金币为活动积分，不具有现金价值。
